# بيانات المصحف

كل بيانات المصحف موجودة جوه التطبيق في `src/data/quran/`، وبتتبني بالسكربت `scripts/build-quran-data.mjs`.

> ⚠️ **ممنوع تعديل ملفات JSON دي بالإيد.** أي تغيير يتعمل في السكربت وبعدين يتشغّل من جديد. (القاعدة 1 في [rules.md](rules.md))

## المصادر

| البيانات | المصدر | الإصدار | الرخصة |
|---|---|---|---|
| نص القرآن بالرسم العثماني (رواية حفص) | موسوعة القرآن الكريم [QuranEnc.com](https://quranenc.com) عبر حزمة npm `quran-json` | 3.1.2 | CC BY 4.0 (لازم ذكر المصدر) |
| ترتيب السطور في الصفحات (مصحف المدينة 1441هـ، 604 صفحة × 15 سطر) | حزمة npm `quran-qcf4`، ملفات JSON بس | 1.1.0 | MIT للـ JSON |
| الأجزاء، الأحزاب، الأرباع، السجدات | حزمة npm `quran-meta` | 7.0.0 | MIT |
| خط النص Scheherazade New | SIL International عبر `@expo-google-fonts/scheherazade-new` | ^0.4.3 | SIL OFL 1.1 |

**مهم:** حزمة `quran-qcf4` فيها كمان ملفات خطوط QCF4، لكن رخصتها **مش بتسمح بإعادة التوزيع**. السكربت ما بيستخدمهاش، وممنوع تتضاف للتطبيق.

**ليه Scheherazade New؟** نص QuranEnc مكتوب بترميز مجمع الملك فهد، وفيه رموز زي تنوين الضم المفتوح (U+065E). اختبرنا كل الحروف المستخدمة في النص: Scheherazade New و Noto Naskh Arabic بيدعموها كلها، أما Amiri Quran فناقصه U+065E.

## إعادة بناء البيانات

```bash
npm run build:quran-data
```

السكربت بيعمل الآتي:

1. ينزّل الحزم التلاتة بـ `npm pack` في فولدر `.quran-sources/` (متجاهل في git).
2. ياخد نص الآيات زي ما هو، من غير أي تعديل.
3. يطابق كل كلمة في النص مع مكانها (الصفحة والسطر) في ملفات التخطيط. المطابقة بهيكل الحروف بس، لأن المصدرين ساعات بيقسموا الكلمات بشكل مختلف (زي «مَالِيَ» كلمة واحدة في النص وكلمتين في التخطيط).
4. **يتحقق** من الآتي، ويقف لو أي حاجة غلط:
   - 114 سورة، و 6236 آية، وعدد آيات كل سورة.
   - كل كلمة لقت مكانها، ومفيش كلمات زيادة.
   - إعادة تركيب كل آية من الصفحات بتطلع النص الأصلي **حرف بحرف**.
   - عدد فروق الصفحات مع `quran-meta` لسه 56 (شوف تحت).
5. يكتب الملفات، ومعاها `meta.json` فيه بصمة SHA-256 للنص كله.

**بصمة النص الحالية:** `39ff52afa15b2e3f1027dda4dfbcfeec5b4001a19430ccc3e141a2d0f1b490c0`

لو البصمة اتغيرت بعد إعادة البناء، يبقى النص نفسه اتغير في المصدر، **ولازم يتراجع من متخصص قبل الدمج**.

## الملفات

| الملف | الحجم | المحتوى |
|---|---|---|
| `ayahs.json` | ~700 KB | قائمة بـ 6236 نص. العنصر رقم `i` هو الآية رقم `i+1` في الترقيم العام |
| `surahs.json` | 11 KB | `{ id, name, nameEn, type, ayahs, firstAyah, page }` لكل سورة |
| `pages.json` | 240 KB | 604 صفحة، كل صفحة `{ page, lines }` (التنسيق تحت) |
| `juz.json` | 2 KB | `{ id, ayahId, surah, ayah, page }` لكل جزء |
| `quarters.json` | 17 KB | 240 ربع: `{ id, hizb, juz, ayahId, surah, ayah, page }` |
| `sajdas.json` | — | أرقام آيات السجدة (15) |
| `meta.json` | — | المصادر، والأعداد، وبصمة النص |

### تنسيق السطر في `pages.json`

كل سطر واحد من تلات أشكال:

```js
["h", 2]                      // عنوان سورة البقرة
["b"]                         // البسملة (نصها من أول آية في الفاتحة)
["w", [9, 0, 0, 1], [10, 0, 7, 0]]   // سطر كلمات
```

في سطر الكلمات، كل جزء بالشكل `[ayahId, from, to, end]`:

- `ayahId`: رقم الآية العام.
- `from` و `to`: رقم أول وآخر كلمة من الآية في السطر ده (الترقيم من 0، والكلمات بتتقسم بالمسافة).
- `end`: `1` لو علامة نهاية الآية في السطر ده.

لو `from > to` و `end = 1`، يبقى السطر فيه علامة نهاية الآية لوحدها.

## فروق معروفة

- **فروق الصفحات مع `quran-meta`:** في 56 آية، صفحة البداية مختلفة بصفحة واحدة بين التخطيط (طبعة 1441هـ) و `quran-meta` (طبعة أقدم). أمثلة: المائدة 77 (120 مقابل 121)، والرحمن 17، وأغلب الفروق في جزء عمّ. التطبيق بيعتمد على التخطيط في كل حاجة، علشان الصفحات تفضل متسقة. **محتاج مراجعة متخصص** للتأكد من مطابقة الطبعة.
- **الشكل:** الصفحات بتترسم بخط عادي (Scheherazade New) بنفس ترتيب السطور، فشكلها **قريب** من المصحف الورقي لكن مش مطابق بالظبط لخط عثمان طه. المطابقة الكاملة محتاجة خطوط QCF برخصة مناسبة (شوف [roadmap.md](roadmap.md)).
